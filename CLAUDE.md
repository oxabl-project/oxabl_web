# oxabl_web — agent notes

Marketing site for oxabl (Astro 7 static build). The playground runs the oxabl
engine as a WASM artifact checked into `src/wasm/`.

## Read `DESIGN.md` before changing anything visual

`DESIGN.md` at the repo root is the authority for this site's visual identity —
the design laws, type roles, colour tokens, page structure, and material rules.
It exists because the first version of this site drifted into framework
defaults and read as generated rather than authored. If a change conflicts with
a law in that document, the law wins, or the law gets amended there first.
Never resolve the conflict silently inside a component.

The name is `oxabl`, lowercase, everywhere — not `ox_abl`, and there is no
`Oxidized_ABL` tagline.

## Updating the oxabl WASM binary

The artifact is generated by the **oxabl** repo (at `~/personal/oxabl`) and vendored
here so the site's build stays deterministic. To regenerate after an upstream
change:

1. Ensure the toolchain is present (one-time):
   - `rustup target add wasm32-unknown-unknown`
   - `cargo install wasm-bindgen-cli --version 0.2.126 --locked`
     The CLI version must match the `wasm-bindgen` crate pin exactly
     (`=0.2.126` in `crates/oxabl_wasm/Cargo.toml`). A mismatch fails at bindgen
     time.
2. From the oxabl checkout (on the target commit):
   `./scripts/build-wasm.sh ~/personal/oxabl_web/src/wasm`
   The script builds `--release`, runs `wasm-bindgen`, and asserts the browser
   recovery machinery is intact (`__wbg_reset_state` exported, no
   exception-handling / `WebAssembly.Tag` injected). Do **not** pass `--verify`
   for a real update — that adds a `debug_panic()` export that must never ship.
3. `pnpm build` to sanity-check the site compiles against the new artifact.
4. Commit `src/wasm/` (usually only `oxabl_wasm_bg.wasm` changes; the glue JS
   and `snippets/` regenerate identically) and deploy.

Keep `oxabl_wasm.js`, `oxabl_wasm_bg.wasm`, and `snippets/` together — the panic
hook is an inline-JS shim the glue imports by relative path.

## Deploying to Cloudflare

Every push to GitHub `master` deploys (`.github/workflows/deploy.yml`); a pull
request only builds. The site is a Cloudflare Worker with static assets only
(`wrangler.jsonc`): no script runs, Cloudflare serves `dist/`, and unknown paths
get `404.html` with a 404 status (not the home page, which search engines would
index under every URL).

- Worker: `oxabl-web`, custom domain `oxabl.org`
- Preview: https://oxabl-web.evan-robertson77.workers.dev
- By hand: `pnpm build && pnpm dlx wrangler@4 deploy`, with
  `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` set
- The workflow reads both from the repository's Actions secrets.

## SEO

- `src/lib/seo.ts` holds the site URL, default title and description, and the
  social image size. `src/layouts/main.astro` renders the canonical link, Open
  Graph and Twitter tags and the JSON-LD from it; `site` in `astro.config.mjs`
  must stay `https://oxabl.org`.
- `public/robots.txt` and `@astrojs/sitemap` (`/sitemap-index.xml`) are served
  from the apex domain. The docs site, `docs.oxabl.org`, has its own.
- `/og.png` is generated at build time by `src/pages/og.png.ts` (satori and
  resvg-js, the `.woff` fonts from `@fontsource/*`, `public/favicon.svg`). Edit
  the tagline or layout there; colours are the `DESIGN.md` tokens as sRGB.
- `pnpm seo:check` (CI runs it after `pnpm build`) fails when a tag, the image,
  `robots.txt`, the sitemap or the 404 handling is missing from `dist/`.
- A page that must stay out of the index passes `noindex` to the layout (it
  drops the canonical and the JSON-LD); `404.astro` does. Cloudflare serves
  `/404` with status 200, so the page itself has to say so.
- A new page needs a unique `title` and `description` props on the layout.
- After a deploy, `pnpm seo:check --live` checks what oxabl.org really serves.
- Search Console: verify the _Domain_ property with a DNS TXT record in
  Cloudflare (covers `docs.` too), then submit the sitemap. A meta tag would go
  in the layout head; a file in `public/`.

## Regenerating the vendored keyword data

`src/data/keyword-counts.json` and `src/data/keywords.json` feed the vocabulary
block. Both are vendored from the **oxabl** repo at `~/personal/oxabl` for the same
reason as the WASM artifact — the site's build must not depend on that checkout.

Regenerate both files from this checkout, passing the oxabl workspace path
explicitly:

```
pnpm keywords:generate -- /home/evanr/personal/oxabl
```

`scripts/generate-keyword-data.mjs` reproduces the `oxabl_codegen` summary
pipeline without building or writing to the oxabl checkout. It parses every row
after the header in `resources/abl_reserved_keywords.txt`, preserving compound
names and minimum abbreviations; depth-first walks
`resources/abl_keyword_index.json` to enrich those reserved rows with the last
documented type and URL for each name; then applies
`resources/keyword_overrides.toml` in codegen order: removals, modifications,
additions. JSON-only names are not unioned into the initial list, alternate
spellings affect lexer generation only, and the callable count comes from final
records classified as functions.

The generator validates the expected codegen-compatible totals before replacing
either vendored file. `keywords.json` contains every final reserved name,
uppercased and ASCII-sorted. Its length must equal
`keyword-counts.json`'s `reserved` count and all entries must be unique.

Check that the vendored data still exactly matches a read-only oxabl workspace:

```
pnpm keywords:check -- /home/evanr/personal/oxabl
```

## Benchmark figures

Benchmark numbers shown on the site must come from the criterion benches in
`~/personal/oxabl` (`cargo bench --workspace`) and use publishable inputs. The
`bench_*.abl` files under `resources/` are committed synthetic fixtures;
`crates/oxabl_schema/fixtures/sp2k.df` is a vendored public Riverside Software
fixture. Report bytes and milliseconds for performance, and retain line counts
for publishable committed fixtures because working ABL developers lead with
lines. Never reference any private codebase — not its name, size, file count,
or pass rate.
